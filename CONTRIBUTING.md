# Contributing to FEOS

Thanks for your interest. FEOS is a governance framework, so changes are held to the same rules it imposes on the projects that use it. Please read this before opening a pull request.

By participating you agree to the [code of conduct](CODE_OF_CONDUCT.md). Report security issues privately, as described in [SECURITY.md](SECURITY.md), and never in a public issue.

## Ways to contribute

- **Bugs:** open an issue with steps to reproduce, the command you ran, its output, and your OS, Python and Claude Code / VS Code versions.
- **Integration drift:** Claude Code and GitHub Copilot change often. If an adapter format (agent front-matter, skill or prompt-file keys, hook payloads) no longer matches the official docs, open an issue with a link to the current documentation.
- **Framework changes** (constitution, gates, rubrics, workflows, agent prompts): open an issue first to discuss the change. These changes affect every adopting project.
- **Platform and domain layers:** new `feos/instructions/10-platform/` or `20-domain/` layers are welcome. Start from `feos/instructions/20-domain/_template.md` and cite your sources.

## Development setup

Requires Python 3.12 or later, which is what CI uses.

```bash
pip install -r scripts/requirements.txt pytest
python scripts/feos_validate.py        # framework self-check
python scripts/feos_render.py --check  # adapters match canonical prompts
python -m pytest -q feos-tests         # behavioural tests
```

All three must pass. The same checks run in CI as the required `feos-validate` status check.

## Rules for changes

1. **Edit the canonical source, then re-render.** Agent prompts live in `feos/agents/*.md`. The files under `.claude/agents/` and `.github/agents/` are generated by `python scripts/feos_render.py`; never edit them by hand.
2. **Behaviour changes need a test.** Every change to `scripts/` comes with a test in `feos-tests/` that fails without the change.
3. **Never weaken a control to make something pass.** Do not relax gates, rubrics, schemas, tests, the guard, the hook, or CI. If you think a control is wrong, propose the change in an issue and explain why.
4. **No invented facts.** Unknowns are written as `TBD(owner, question)`. Do not add versions, citations or thresholds you have not verified.
5. **Protected paths** (`feos/`, `.github/`, `.claude/`, `scripts/feos_*`, `feos-tests/`, `CLAUDE.md`, `AGENTS.md`) require review by a code owner (see `.github/CODEOWNERS`). In Claude Code, the protection hook blocks edits to them unless the session runs with `FEOS_FRAMEWORK_EDIT=1`.

## Commits and pull requests

- Write a clear commit subject in the imperative mood, in [Conventional Commits](https://www.conventionalcommits.org/) style (`fix(guard): ...`, `docs: ...`).
- Commits produced by FEOS agents must carry `FEOS-Agent: <agent-id>` and, for backlog work, `Refs: TK-###` trailers. `scripts/feos_guard.py` checks them in CI.
- Fill in the pull request template, including the commands you ran and their exit codes.
- Keep pull requests focused. Unrelated clean-ups belong in a separate PR.
- Add a line under `Unreleased` in [CHANGELOG.md](CHANGELOG.md) for user-visible changes.
